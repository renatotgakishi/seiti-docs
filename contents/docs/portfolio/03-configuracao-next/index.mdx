O Payload já vem com Next.js, mas precisamos ajustar 3 coisas que quebram 90% dos projetos de portfólio.

## O Problema Real

<Note type="warning" title="Erro que você já viu">
`import './styles.css'` não aplica nada, ou `Module not found: @/blocks/...` no build.
</Note>

## 1. Alias @/

No `tsconfig.json`:

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["./src/*"],
      "@/payload-types": ["./src/payload-types.ts"]
    }
  }
}
```

<Steps>
  <Step title="Teste o alias">
    Crie `src/blocks/test.ts` e importe em `payload.config.ts` com `@/blocks/test`. Se não der erro, o alias funciona.
  </Step>
  <Step title="Reinicie o TS Server">
    No VSCode: Ctrl+Shift+P -> Restart TS Server. Isso evita falso erro vermelho.
  </Step>
</Steps>

## 2. CSS Modules vs Global

O Next 15 com Turbopack ignora CSS global dentro de `blocks/`. Use sempre CSS Modules.

<FileTree>
  <Folder name="blocks" defaultOpen={true}>
    <Folder name="SobreBlock">
      <File name="Component.tsx" />
      <File name="config.ts" />
      <File name="styles.module.css" />
    </Folder>
  </Folder>
</FileTree>

```tsx
// Component.tsx - CERTO
import styles from './styles.module.css'
export const SobreBlock = () => <section className={styles.wrapper}>...

// ERRADO - não vai aplicar
import './styles.css'
```

## 3. next.config.ts essencial

```ts
import { withPayload } from '@payloadcms/next/withPayload'

const nextConfig = {
  // necessário para Payload 3.0
  experimental: {
    reactCompiler: false,
  },
}

export default withPayload(nextConfig)
```
